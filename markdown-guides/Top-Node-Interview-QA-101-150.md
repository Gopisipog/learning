# Node.js / Security / MongoDB Interview Questions 101–150 – Learning Guide

_Source: Top-200-Node-Interview-Questions-pdf.txt_

101. **What are common security risks in Node.js / Express applications?** – Typical risks include XSS, SQL/NoSQL injection, CSRF, insecure authentication, sensitive data exposure, misconfigured CORS, and using vulnerable dependencies.
102. **How do you protect a Node/Express app against XSS attacks?** – Encode or escape user input in views, use templating engines that escape by default, validate/sanitize inputs, use security headers (e.g., Content-Security-Policy via Helmet), and avoid injecting raw HTML.
103. **How do you prevent SQL or NoSQL injection in Node.js?** – Always use parameterized queries or query builders, avoid string concatenation with user input, validate and sanitize inputs, and use ORM/ODM APIs (e.g., Mongoose) that handle parameters safely.
104. **What is Helmet in Express.js and how does it improve security?** – Helmet is an Express middleware collection that sets various HTTP security headers (CSP, X-Frame-Options, HSTS, etc.) to reduce common attack surfaces.
105. **What is rate limiting in APIs and why is it important?** – Rate limiting restricts how many requests a client can make in a time window to help prevent abuse, brute-force attacks, and DoS on your Node API.
106. **How should you store secrets and configuration values in a Node.js application?** – Use environment variables (.env files with a loader like `dotenv`), secret stores (Vault, cloud key vaults), and never hard-code secrets in source control.
107. **What is CSRF and how can you mitigate it in a Node.js web app?** – CSRF tricks a logged-in user’s browser into sending unwanted requests; mitigate via anti-CSRF tokens, SameSite cookies, checking origin/referrer headers, and using frameworks/middleware that provide CSRF protection.
108. **How does CORS relate to API security?** – CORS controls which origins can access your API from the browser; misconfigured CORS can expose APIs to unintended websites, so you should explicitly whitelist trusted origins and methods.
109. **Why is HTTPS/TLS important for Node.js APIs?** – HTTPS encrypts traffic between client and server, protecting credentials and sensitive data from eavesdropping or tampering in transit.
110. **What is a process manager like PM2 and why use it in production?** – PM2 keeps Node processes running, restarts them on crashes, supports clustering and log management, and simplifies zero-downtime deployments.
111. **How can you improve the performance of a Node.js application?** – Use efficient algorithms, leverage caching (in-memory or Redis), enable gzip compression, minimize blocking code, paginate results, and scale horizontally with clustering or multiple instances.
112. **What is the Node.js cluster module and when would you use it?** – The cluster module lets you run multiple worker processes sharing the same server port so you can use multiple CPU cores and handle more concurrent requests.
113. **How do you implement logging in a Node/Express app?** – Use logging libraries like `winston` or `pino`, log structured JSON, capture error and request logs, and send them to files or centralized logging systems.
114. **How do you handle environment-specific configuration for deployment?** – Use environment variables or separate config files per environment (dev/test/prod), and load the correct settings at startup based on `NODE_ENV`.
115. **What is the role of a reverse proxy (like Nginx) in front of a Node.js app?** – A reverse proxy can terminate TLS, handle load balancing, serve static assets, apply caching, and forward requests to one or more Node backend instances.
116. **What is the difference between vertical and horizontal scaling for Node.js?** – Vertical scaling means giving a single server more resources (CPU/RAM), while horizontal scaling means adding more Node instances or servers behind a load balancer.
117. **What is a memory leak in Node.js and how might you detect it?** – A memory leak is when memory usage grows continuously due to unreleased references; detect it by monitoring process memory, using heap snapshots, and profiling tools in Node/Chrome DevTools.
118. **What types of tests are common in Node.js projects?** – Unit tests (small, isolated), integration tests (modules working together or with real DB), and end-to-end tests (full request flow through the system).
119. **What testing frameworks are commonly used in Node.js?** – Popular choices include **Jest**, **Mocha** (often with Chai), **Jasmine**, and supertest for HTTP API testing.
120. **What is supertest and when would you use it?** – Supertest is a library for testing HTTP servers in Node; you use it to send requests to your Express app and assert on the responses without starting a real network server.
121. **How should you structure tests in a Node.js codebase?** – Place tests alongside code or in a separate `tests`/`__tests__` folder, mirror the app structure, name tests clearly, and separate unit, integration, and e2e tests for clarity.
122. **What is WebSocket and how does it differ from HTTP?** – WebSocket is a full-duplex, persistent communication channel over a single TCP connection, unlike HTTP which is request–response and typically short-lived.
123. **When would you choose WebSockets instead of REST APIs?** – Use WebSockets for real-time, bidirectional communication (chat, live dashboards, multiplayer games) where the server must push frequent updates to clients.
124. **How can you implement WebSockets in Node.js?** – Use libraries like `ws` (WebSocket server/client) or frameworks like Socket.IO on top of Node to handle WebSocket connections and events.
125. **What is Socket.IO and how is it different from raw WebSocket?** – Socket.IO is a higher-level library that offers automatic reconnection, rooms, broadcasting, and fallbacks when WebSockets aren’t available, while raw WebSocket is a lower-level protocol.
126. **What is MongoDB and how does it differ from a relational database?** – MongoDB is a document-oriented NoSQL database that stores JSON-like documents in collections instead of rows in tables, with flexible schemas.
127. **What are database, collection, and document in MongoDB?** – A **database** contains collections; a **collection** groups related documents; a **document** is a JSON-like object representing a single record.
128. **How do you connect a Node.js application to MongoDB?** – Use the official MongoDB Node driver (`mongodb`) or an ODM like Mongoose, providing a connection URI (e.g., `mongodb://...`) and initializing the connection during app startup.
129. **What is CRUD in MongoDB and how is it done from Node.js?** – CRUD stands for Create, Read, Update, Delete; from Node you typically call methods like `insertOne`, `find`, `updateOne`, and `deleteOne` on collection objects.
130. **How do you model one-to-many relationships in MongoDB?** – Either **embed** related documents (array of sub-documents) in a parent document or **reference** them using ObjectId fields, depending on access patterns and size.
131. **What are MongoDB query operators?** – They are special keys like `$eq`, `$gt`, `$lt`, `$in`, `$and`, `$or`, etc., used inside queries to express conditions beyond simple equality.
132. **What is projection in MongoDB queries?** – Projection specifies which fields to include or exclude in the query result, often done with a second parameter to `find` (e.g., `{ name: 1, _id: 0 }`).
133. **What are indexes in MongoDB and why are they important?** – Indexes are data structures that speed up queries by allowing MongoDB to locate documents without scanning the entire collection, at the cost of extra storage and write overhead.
134. **What is a compound index in MongoDB?** – A compound index is an index on multiple fields (e.g., `{ status: 1, createdAt: -1 }`) that supports queries filtering or sorting on those fields in order.
135. **What is a covered query in MongoDB?** – A covered query is one where all the fields in the query and projection are contained in the index itself, so MongoDB doesn’t need to examine the actual documents.
136. **What is Mongoose and why would you use it with Node and MongoDB?** – Mongoose is an Object Data Modeling (ODM) library that provides schemas, models, validation, middleware, and a higher-level API over the MongoDB driver.
137. **What are schemas and models in Mongoose?** – A **schema** defines the structure and rules (types, defaults, validation) for documents; a **model** is a compiled constructor based on the schema used to create and query documents.
138. **How do you define a simple Mongoose schema?** – You create a new `mongoose.Schema` with a field definition object (e.g., `{ name: String, age: Number }`) and compile it into a model with `mongoose.model('User', userSchema)`.
139. **How do you handle relationships between collections in Mongoose?** – Use ObjectId references in schemas (e.g., `{ user: { type: Schema.Types.ObjectId, ref: 'User' } }`) and call `.populate()` to load related documents.
140. **What are pre and post middleware (hooks) in Mongoose?** – They are functions that run before or after certain operations (save, validate, find, remove), allowing you to add side effects or enforce invariants.
141. **What is a virtual property in Mongoose?** – A virtual is a property defined on the schema that is not stored in Mongo but computed dynamically from other fields (e.g., `fullName` from `firstName` and `lastName`).
142. **How can you implement pagination in MongoDB queries from Node.js?** – Use `limit` and `skip` or range-based pagination (e.g., using `_id` or timestamps) in queries, and pass page/size parameters from clients.
143. **What is an ObjectId in MongoDB and what is it used for?** – ObjectId is the default unique identifier type for documents; it encodes a timestamp and random values and is used as the `_id` field.
144. **How do you handle multi-document transactions in MongoDB from Node.js?** – Use MongoDB sessions and the `withTransaction` API (available in replica sets/sharded clusters) to execute multiple operations atomically.
145. **What is connection pooling in MongoDB drivers and why is it useful?** – Connection pooling maintains a pool of reusable database connections so each request doesn’t have to create a new connection, improving performance and scalability.
146. **What is a TTL index in MongoDB and when would you use it?** – A TTL (Time-To-Live) index automatically deletes documents after a specified time, useful for expiring logs, sessions, or temporary data.
147. **What is the MongoDB aggregation framework?** – It’s a powerful pipeline-based system (`$match`, `$group`, `$project`, etc.) used to transform and analyze data directly on the server side.
148. **What is the difference between using the MongoDB native driver and Mongoose?** – The native driver is lower-level and closer to Mongo’s commands; Mongoose adds schemas, validation, middleware, and a richer model abstraction on top of the driver.
149. **How would you design collections for a typical Node.js REST API?** – Identify resources, create collections per major resource, choose embedding vs referencing for relations, add necessary indexes, and design documents around read/write patterns.
150. **What are some best practices when using MongoDB with Node.js in production?** – Use proper indexes, monitor performance, handle connection errors, validate data at the app and schema levels, secure the database, and back up regularly.
